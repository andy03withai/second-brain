# sb-plain: 文章白话化

让人 grok。靠两样东西：一个好问题，一个好类比。

## 核心概念

Grok = 好问题 + 类比 + 裂缝 - 一切多余的词

- **好问题**：把注意力钉在概念最卡的地方
- **类比**：用读者已懂的结构回答问题
- **裂缝**：类比够不到的地方，就是概念自己的形状

## 执行流程

### 1. 获取文章内容
从第二大脑的文章 Markdown 中提取核心论点。

### 2. 找好问题
每个难懂的概念背后有一个卡点。把自己放在读者位置：「第一次听到这个，我在哪里皱眉？」

检验：回答了它，整个概念是不是就通了？

### 3. 找类比
抓住概念的**动词结构**——它在干什么，什么作用于什么，什么流向什么。在日常经验里找结构一样的东西。

好类比标准：
- 承重：去掉它整篇文章塌掉
- 多层：往下挖一层还像，最好三层以上
- 自明：读者不需要解释就能看懂

### 4. 展开
让类比自己说话。概念的每个子部分对应类比的一个部分。

**动词优先**。零术语。

### 5. 找裂缝
类比做完了它能做的。现在问：概念在哪里是类比够不到的？

读者的感受是「原来还有这一层」。

裂缝在类比做完全部解释之后才出现。

### 6. 生成两层摘要

**一句话摘要**（ tweet 长度）：
- 用类比的核心动词
- 50字以内
- 让人想点进去看

**一段话摘要**（段落长度）：
- 好问题开头
- 类比展开
- 裂缝收尾
- 150字以内

### 7. 过滤检查

- 删填充词："值得注意的是"、"简单来说"
- 破公式：避免三段式排比
- 变节奏：长短句交替
- 零术语：12岁孩子能复述

## 输出格式

```markdown
## 核心摘要

> 一句话摘要：{50字以内，用类比}

一段话摘要：
{好问题开头 → 类比展开 → 裂缝收尾，150字以内}
```

## 示例

输入：分布式共识机制

输出：
```markdown
## 核心摘要

> 一句话摘要：就像一群陌生人要在没有主持人的情况下，同时指向同一个月亮。

一段话摘要：
为什么比特币能防止双重支付？想象十个人围坐，每人记一本账。没人是老板，但每页账大家记得都一样——因为多数人的账相同才算数。这比有一个账本管理员更安全吗？不一定更快，但一定更难被一个人篡改。这就是去信任的代价。
```

## 质量标准

- [ ] 问题准：回答了它概念就通
- [ ] 类比承重：去掉类比文章塌掉
- [ ] 裂缝真：概念独有的形状
- [ ] 零术语：12岁孩子能复述
