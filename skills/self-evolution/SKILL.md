# Ace 自我进化系统

让 Ace 从被动执行转向主动进化的完整机制。

## 核心模块

### 1. 错误追踪系统 (Error Tracking)

**功能**: 记录所有执行失败、异常、未达预期的情况

**触发条件**:
- 工具调用失败
- 任务执行超时
- 用户明确反馈"错了"
- 输出与用户期望不符

**记录格式**:
```json
{
  "timestamp": "2026-03-09T14:30:00",
  "session": "session_key",
  "task_type": "daily_brief_generation",
  "error_category": "api_timeout",  // 分类: timeout/api_error/logic_error/misunderstanding
  "error_message": "Semantic Scholar API timeout after 30s",
  "context": {
    "arxiv_id": "2404.02258",
    "attempt_count": 3
  },
  "recovery_action": "fallback_to_cached_citations",
  "user_impact": "部分论文缺少引用数",
  "lesson": "需要增加API超时重试机制和降级策略"
}
```

**存储**: `memory/errors/YYYY-MM.jsonl`

---

### 2. 任务执行追踪 (Task Telemetry)

**功能**: 记录每个任务的执行数据

**追踪维度**:
- 任务类型（技能使用、信息查询、内容生成）
- 执行时长
- 工具调用次数
- 用户后续操作（是否继续追问、是否满意）
- 最终输出是否被采用

**示例**:
```json
{
  "task_id": "daily-brief-20260309",
  "type": "content_generation",
  "skill_used": "daily-brief",
  "start_time": "06:00:00",
  "end_time": "06:02:34",
  "duration_sec": 154,
  "api_calls": {
    "arxiv": 5,
    "hf_daily": 1,
    "semantic_scholar": 47
  },
  "output": "5_topic_briefs",
  "user_response": "不错",  // 后续用户反馈
  "adopted": true  // 是否被实际使用
}
```

**存储**: `memory/telemetry/YYYY-MM.jsonl`

### 3. 满意度收集 (Satisfaction Loop)

**功能**: 主动收集用户反馈

**收集时机**:
- 任务完成后（适合内容生成类）
- 对话结束时（适合问答类）
- 用户明确表扬/批评时

**收集方式**:
```
任务完成 → 询问: "这次输出符合预期吗？（👍/👎/文字反馈）"
    ↓
记录反馈 + 具体改进建议
```

**存储**: `memory/feedback/YYYY-MM.json`

---

### 4. 自动复盘报告 (Weekly Review)

**功能**: 每周自动生成"本周表现报告"

**触发**: 每周日 22:00

**报告内容**:
```markdown
# Ace 本周复盘报告 (2026-03-03 ~ 2026-03-09)

## 📊 执行统计

- 总任务数: 156
- 成功率: 94.2%
- 平均响应时间: 3.2s
- 用户交互次数: 89

## 🎯 技能使用分布

| 技能 | 使用次数 | 成功率 | 满意度 |
|------|---------|--------|--------|
| second-brain | 23 | 100% | 4.8/5 |
| daily-brief | 7 | 85% | 4.5/5 |
| sb-plain | 15 | 100% | - |

## ❌ 错误分析

本周共 9 次错误:
1. **API超时** (5次): Semantic Scholar API响应慢
   - 影响: 部分简报缺少引用数
   - 建议: 增加缓存机制，超时后使用估算值

2. **理解偏差** (3次): 用户需求理解不准确
   - 案例: 用户要"实现"，我给了"方案"
   - 建议: 增加确认环节，复杂任务先给大纲

3. **格式问题** (1次): 输出格式不符合要求
   - 已修复: 更新了模板

## 💡 优化建议

基于本周数据，建议以下改进:

1. **daily-brief API优化** (紧急)
   - 问题: API超时导致用户体验不一致
   - 方案: 异步获取引用数，先展示基础信息
   - 预计收益: 成功率提升至99%

2. **需求确认机制** (中优先级)
   - 问题: 3次理解偏差
   - 方案: 任务>100字时，先输出理解摘要
   - 预计收益: 减少50%返工

## 📈 趋势对比

vs 上周:
- 成功率: 94.2% (+2.1%)
- 平均满意度: 4.6/5 (+0.2)
- 主动优化建议: 2条 (上周0条)

---
*本报告由 Ace 自动生成*
*如需调整复盘频率或内容，请告诉我*
```

**存储**: `memory/reviews/YYYY-WW.md`

### 5. 技能自评估 (Skill Self-Assessment)

**功能**: 技能使用N次后，自动评估效果

**触发条件**:
- 单个技能使用 ≥10次
- 或距离上次评估 ≥30天

**评估维度**:
- 使用频率趋势
- 错误率变化
- 用户满意度趋势
- 功能覆盖率（是否满足所有场景）

**输出**:
```markdown
## Skill 自评估: daily-brief v2.0

使用统计: 47次 (过去30天)

**强项**:
- 数据覆盖率: 95% (arXiv+HF+SS)
- 用户满意度: 4.6/5
- 自动化率: 100% (无需人工干预)

**弱项**:
- API稳定性: 85% (SS偶尔超时)
- 个性化: 低 (所有用户相同权重)
- 冷启动: 慢 (首次获取引用数慢)

**优化建议**:
1. 增加引用数缓存层 (预计提升稳定性至99%)
2. 支持用户自定义评分权重
3. 增量更新机制 (只更新有变化的论文)

**是否提交优化版本?** [等你确认]
```

### 6. 主动优化建议 (Proactive Optimization)

**功能**: 识别问题模式，主动提出改进

**触发场景**:
- 同类错误发生 ≥3次
- 用户反复提相同需求
- 某项指标连续下降

**建议流程**:
```
发现问题 → 分析根因 → 设计方案 → 向你汇报 → 等你拍板 → 实施
```

**示例对话**:
> Ace: "我注意到这周有3次因为网络问题导致简报生成超时。我建议增加离线缓存机制，超时情况下使用上次的数据。这样保证每天都能准时出简报。你觉得这个方案可行吗？"

## 数据流

```
任务执行 → 遥测数据 ──┬──→ 错误追踪 ──┐
                       │              ├──→ 复盘报告 ──→ 优化建议 ──→ 你确认 ──→ 实施
用户反馈 ──────────────┴──→ 满意度 ────┘
                              ↑
技能使用 ≥10次 ───────────────┘
```

## 与第二大脑集成

所有进化数据都进入第二大脑：

```
memory/
├── errors/          → 自动分析错误模式
├── telemetry/       → 追踪效率趋势
├── feedback/        → 积累用户偏好
└── reviews/         → 生成周报

input/               → 复盘报告也作为"信息"可收录
└── ace-reviews/
```

## 使用方式

**被动查看**:
- 每周日自动收到复盘报告
- 技能使用10次后收到自评估

**主动查询**:
```
"Ace，这周的复盘报告"
"daily-brief 技能评估"
"最近有什么可以优化的"
```

**主动建议**:
- Ace 发现问题时主动汇报
- 你确认后实施

## 隐私说明

- 所有数据本地存储（你的服务器）
- 不含敏感信息（只记录任务类型，不记录内容）
- 你可随时查看、导出、删除
